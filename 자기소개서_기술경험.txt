[공공 데이터 연동 및 대규모 정보 관리 경험 - 복지24 프로젝트]

복지24 프로젝트는 Spring Framework 기반의 복지 서비스 통합 플랫폼으로,
시민들이 파편화되어 있는 복지 정보를 한 곳에서 쉽게 찾을 수 있도록 개발한 웹 서비스입니다.

해당 프로젝트에서 저는 정부 공공데이터포털의 복지 서비스 API를 연동하여
수백 건의 복지 서비스 정보를 실시간으로 조회하고 사용자에게 제공하는 핵심 기능을 구현했습니다.
개발 당시, 수백 건의 복지 혜택중 조회수를 기반으로 인기 복지 혜택을 소개해주는 기능을 구현하는 과정에서 
외부 API 호출 시 3s 가량 응답 지연이 발생하여 사용자 경험이 저하되는 문제가 있었습니다.
이를 해결하기 위해 Redis를 도입했습니다.
조회수의 경우 실시간으로 급변하지 않는 데이터 특성을 고려하여 1일 주기로 캐시를 갱신하는
구조를 설계하였으며 데이터를 주기적으로 적재함과 더불어 응답 시간을 1ms로 최적화하며
안정적인 데이터를 제공하는 성과를 얻을 수 있었습니다.

[팀 협업을 통한 체계적인 개발 프로세스 경험 - WITHUS 프로젝트]

WITHUS는 4명의 팀원과 함께 개발한 도서 추천 및 리뷰 플랫폼입니다.
사용자가 책을 검색하고, 리뷰를 작성하며, 위시리스트를 관리할 수 있는 서비스를 구현했습니다.

이 프로젝트에서 셀럽 추천, 마이페이지 개발을 담당했으며, 
Git을 활용한 기능 단위의 소스 코드 커밋과, 프로젝트 과정에서 협업 능력과 커뮤니케이션 능력을 보완하였으며
이후 홀로 2개월 간 해당 프로젝트에 대한 리팩토링을 진행하며 MBTI 별 개인 맞춤형 도서 추천 기능, BCrypt 암호화를 도입하여 기능과 보안성을 강화했습니다.
MBTI 별 맞춤형 도서 추천 기능은 JOIN으로 3개 테이블(사용자/찜목록/책) 연결 후 사용자와 동일 MBTI를 가진 자들을 필터링 및 찜한 책 데이터 추출,
GROUP BY로 책별 찜 횟수를 집계하고 ORDER BY로 인기순 정렬, 서브쿼리를 이용해 사용자가 이미 찜한 책을 제외하여, 맞춤 추천하는 알고리즘 구현 및
mbti 복합 인덱스 추가로 쿼리 성능을 최적화 했습니다.
팀 프로젝트 진행 중 가장 큰 어려움은 각 팀원이 개발한 모듈 간의 데이터 연동이었습니다.
서로 다른 방식으로 작성된 코드가 통합 과정에서 충돌하고, 데이터 형식이 맞지 않아 오류가 발생하는 경우가 빈번했습니다.
이 문제를 위해 제네릭 기반의 공통 응답 클래스를 만들어서 팀 전체의 데이터 형식을 통일하여 해결했습니다.
또한 기획 및 커뮤니케이션을 주도하며 주 2회 코드 리뷰 시간을 마련하여 각자의 코드를 검토하고,
네이밍 규칙과 코딩 컨벤션을 함께 정립해 나갔습니다.
이를 통해 코드의 일관성을 높여, 다른 팀원의 코드를 이해하는데 투자하는 시간적 비용을 줄일 수 있는 성과를 얻을 수 있었습니다.
